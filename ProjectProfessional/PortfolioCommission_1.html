Web page Setup

Since the client simply wants to recreate a webpage from an existing design, such as one built on Wix, the process has been much easier. The layout, colors, typography, and content structure are already defined, so I don't have to spend time on design decisions or wait on revisions. I can focus on translating what's already there into clean, working code, and I already have a clear vision of the end result. For the build, I use HTML for the structure, CSS for styling and responsive layout, and a small amount of JavaScript to code the transition effect when navigating between the navbar tabs. Keeping the JavaScript minimal keeps the site lightweight and fast to load. It also makes it easier to maintain, and it avoids the bloat that website builders often add. The result is a site that looks like the original design but gives the client full control over the code and hosting.

Form Setup

Since the site is static and has no backend, I used Formspree to handle the contact form. I created a form in my Formspree account, which gave me a unique endpoint, and pointed the HTML form's action at it. Every input has a name attribute, which is how Formspree knows which fields to collect and include in the email.

Show Code — contact.html (form) 

<form class="contact-form" id="contact-form"
action="https://formspree.io/f/your-form-id" method="POST" novalidate>
<label>First name *<input type="text" name="first_name" required autocomplete="given-name"></label>
<label>Last name *<input type="text" name="last_name" required autocomplete="family-name"></label>
<label>Email *<input type="email" name="email" required autocomplete="email"></label>
<label>Subject<input type="text" name="subject"></label>
<label class="wide">Message<textarea name="message" rows="4"></textarea></label>
<button type="submit" class="submit-btn">Submit</button>
<p class="form-status" role="status" aria-live="polite"></p>
</form>

I added novalidate to turn off the browser's default validation pop-ups, so I could handle validation myself and keep the error messages consistent with the site's design. The autocomplete attributes let browsers autofill the fields, and the status paragraph at the bottom uses aria-live="polite" so screen readers announce the result.

Validation

On submit, a short script stops the default page reload and checks each required field. Empty fields, or an email that doesn't look like an address, get an invalid class that I can style in CSS, and the visitor is asked to complete the required fields.

Show Code — main.js (validation) 

form.addEventListener("submit", function (e) {
  e.preventDefault();
  var ok = true;
  form.querySelectorAll("[required]").forEach(function (el) {
    var bad = !el.value.trim() ||
      (el.type === "email" && !/^\S+@\S+\.\S+$/.test(el.value));
    el.classList.toggle("invalid", bad);
    if (bad) ok = false;
  });
  if (!ok) {
    status.textContent = "Please fill in the required fields (*).";
    return;
  }
  // ...send the form
});

Sending Without Leaving the Page

If everything is valid, the form is sent in the background with fetch and FormData. The Accept: application/json header tells Formspree to reply with JSON instead of redirecting to its own thank-you page, so the visitor stays on my site. The form shows "Sending…", then resets and confirms on success, or shows a friendly error message if something goes wrong.

Show Code — main.js (fetch) 
status.textContent = "Sending…";
fetch(form.action, {
  method: "POST",
  body: new FormData(form),
  headers: { Accept: "application/json" }
})
  .then(function (r) {
    if (!r.ok) throw new Error("Request failed");
    form.reset();
    status.textContent = "Thanks! Your message has been sent.";
  })
  .catch(function () {
    status.textContent = "Something went wrong. Please try again later.";
  });

Result

Formspree forwards each submission to the client's inbox and keeps a copy in its dashboard. The client gets a working contact form with no server code and no hosting cost, which fits a site hosted on GitHub Pages.
